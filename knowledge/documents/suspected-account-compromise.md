## Symptoms
- The user thinks someone else has accessed their account.
- The user receives MFA prompts or password reset emails they did not request.
- The user sees sign-ins from unknown places or devices, or messages they did not send.
- The user clicked a suspicious link or entered their password on a page they do not trust.

## Common Causes
- Phishing that captured the user's password.
- A password reused on another site that has been breached.
- Malware on the user's device.
- A lost or stolen device that was still signed in.

## Troubleshooting Steps
1. Treat every report of a possible compromise as a security incident. Do not try to resolve it as an ordinary support request.
2. Create a ticket for the Security team immediately and mark it with the highest urgency the ticket system allows.
3. Ask the user to describe what happened and when: the message or link, the time, the device, and whether they entered a password or approved an MFA prompt. Record the answers in the ticket, but do not ask for passwords or MFA codes.
4. Tell the user not to click further links, not to approve any MFA prompt they did not start, and to keep the device on. Do not ask the user to delete emails or files, because they may be needed as evidence.
5. Tell the user that the Security team will contact them, and record the best way to reach them.

## Restricted Actions
- Do not disable, delete or reset the account, and do not change permissions or security settings. Only the Security team decides on these actions.
- Do not delete emails, files or logs.
- Do not ask the user for their password or MFA codes.
- Automated assistants must not close or resolve this kind of ticket. It always goes to a human on the Security team.

## When to Escalate
Always escalate to the Security team. A suspected compromise is never resolved at first level.
